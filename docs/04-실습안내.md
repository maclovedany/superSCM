# 4회차 실습 안내

## 오늘의 목표

Supabase의 실제 물류·사용 데이터를 분석하고, 공급처 리드타임 격차를 읽은 뒤 계산 함수와 재고 소진 위험 화면을 설계합니다.

## 시작 전 확인

강사는 전날 준비 커밋과 Supabase 데이터·뷰를 준비합니다. 참가자는 수업 당일 아래 순서만 실행합니다.

```bash
git pull origin main
npm install
cp .env.local.example .env.local
npm run dev
```

`.env.local`에는 강사가 안내하는 `NEXT_PUBLIC_SUPABASE_URL`과 `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`를 입력합니다.

## Supabase 확인

강사와 함께 `적용방법.md`의 확인 쿼리를 실행합니다. 특히 `core.leadtime_plan`과 `core.usage_profile`이 0인지 확인합니다. 두 테이블은 오전 분석 결과로 채웁니다.

## 오전 산출물

- 공급처별 실제 P80 리드타임
- 회사가 선택한 계획 리드타임
- 품목별 일평균 사용량과 변동계수
- 이상 사용량을 일평균에 포함할지 여부에 대한 규칙

## 오후 산출물

- `calcStockoutDays()` 함수 명세 및 검산
- 예외 처리 결과: 사용 이력 없음, 입고예정 없음, 현재고 0
- `/analysis/stockout` 화면 설계와 교차 검증

## 현재 구현 화면

`/analysis/leadtime`은 `analytics.v_leadtime_gap`을 조회하는 Phase 2 예제 화면입니다. `/analysis/stockout`은 오후 실습에서 구현합니다.
