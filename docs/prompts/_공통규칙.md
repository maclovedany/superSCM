## 3. 반드시 지킬 규칙 (AGENTS.md 요약 + 이 프로젝트에서 자주 걸리는 것)

1. **계산은 SQL 이 한다.** TypeScript 에서 평균·분위수·합계를 구하지 않는다. 화면과 lib 는 조회·병합·표시만.
2. **계산 불가를 숫자로 채우지 않는다.** `null` + 사유 코드. 화면은 `EmptyValue`. 정렬은 `nullsLast`.
3. **화면은 `analytics` 뷰만 조회. `raw` 는 앱에서 절대 부르지 않는다** (REST 미노출, error.md #9). 쓰기는 `core` 의 security definer 함수를 rpc 로 부른다.
4. **권한은 서버에서.** 서버 컴포넌트 첫 줄에서 `requireUser()` / `requireAdmin()`. **Server Action 에서는** 관리자 전용이면 `requireAdminOrThrow()`, 로그인 사용자용이면 `getSessionUser()` 를 쓰고 null 이면 `{ error: '로그인이 필요합니다.' }` 를 반환합니다. `requireUser()` 는 `redirect()` 를 던지므로(NEXT_REDIRECT) 액션의 try/catch 가 삼켜 버립니다 — 액션에서 쓰지 마세요.
5. **KPI 카드는 눌러서 목록을 좁힌다.** `FILTERS: FilterSpec<T>[]` 한 곳. 좁힐 수 없는 카드엔 `filter` 를 주지 않고, 파일에 `// kpi-filter: 없음 — <이유>` 를 적는다.
6. **차트는 `components/chart/` 만 recharts 를 import.** 화면은 래퍼만.
7. **`design.md` 토큰만.** 화면 파일에 hex 색·px 간격 금지. `var(--*)` 와 기존 CSS 클래스. 새 CSS 클래스가 꼭 필요하면 `styles/components.css` 끝에 `/* ── <이름> ── design.md §N */` 주석과 함께 추가한다. 화면별 CSS 파일 금지.
8. **한국어.** 화면 문구·주석·문서. 컬럼명·변수명은 영어.
9. **`'use server'` 파일은 async 함수만 export.** 상수·타입은 같은 폴더 `state.ts` (error.md #10). `lib/use-server-exports.test.ts` 가 검사한다.
10. **PL/pgSQL `RETURNS TABLE` 컬럼과 같은 이름의 테이블 컬럼은 항상 별칭으로 한정** (error.md #11).
11. **PostgREST 1,000행 상한.** 집계는 SQL 뷰에서 끝낸다. 목록 조회는 `.limit()` 을 명시한다.
12. `round(double precision, int)` 없음 → `::numeric` 캐스팅 후 round. set-returning 함수는 `from` 절로.
13. 정책값(리드타임 · 서비스 수준 · 여유일 등)을 코드에 하드코딩하지 않는다. `core.policy_config` / `core.item_policy` / `core.service_level` 을 읽는다.
14. 새 SQL 파일은 `create table if not exists` · `create or replace view/function` · `drop policy if exists` 로 **재실행해도 안전**하게. 파일 끝에 확인용 `select` 를 붙인다. 파일 머리에 "먼저 실행할 파일" 을 적는다.
15. **뷰를 `create or replace` 로 바꿀 때 컬럼을 빼거나 순서를 바꾸면 PostgreSQL 이 거부한다.** 컬럼을 빼야 하면 `drop view ... cascade` 후 재생성하고, 그 뷰에 의존하는 뷰도 같은 파일에서 다시 만든다.
16. `Planned` 자리표시자 화면을 실제 화면으로 바꿀 때는 `components/ui/planned.tsx` import 를 지운다.

## 4. 하지 말 것

- **`git commit` · `git add` 하지 않는다.** 작업 트리에만 남긴다. 커밋은 사용자가 한다.
- **`lib/menu.ts` · `step.md` · `error.md` · `ARCHITECTURE.md` 를 고치지 않는다.** 컨트롤러가 한다. 바꿔야 할 내용(ready 플래그 · 새 오류)은 보고서에 적는다.
- 서브에이전트를 띄우지 않는다.
- 지시서에 없는 화면·기능을 덧붙이지 않는다 (YAGNI).
- `components/workflow/*` 레거시는 건드리지 않는다.
- DB 를 직접 실행할 수 없다. SQL 은 파일로만 만든다. 문법은 `psql -f 파일 --set ON_ERROR_STOP=1` 로 검사할 수 없으므로(접속 불가), **파일을 처음부터 끝까지 다시 읽어 세미콜론·괄호·별칭을 눈으로 검사**한다.

## 6. 보고서

지시서가 지정한 보고서 파일에 다음을 씁니다.

- 만든 것 / 못 만든 것과 이유
- 파일 목록 (신규 · 수정)
- 실행한 검증 명령과 결과 (tsc · test · build · grep)
- **DB 실행 순서** — 사용자가 SQL Editor 에서 실행할 파일과 순서, 실행 후 확인할 select
- `lib/menu.ts` 에서 ready 로 바꿔야 할 href
- 새로 겪은 오류와 해결 (error.md 에 추가할 내용)
- 다음 단계가 알아야 할 인터페이스 (뷰 컬럼 · 함수 시그니처 · lib 함수)
- 걱정되는 점

마지막 메시지는 15줄 이내: 상태(DONE / DONE_WITH_CONCERNS / BLOCKED / NEEDS_CONTEXT) · 검증 요약 · 보고서 경로 · 우려.
