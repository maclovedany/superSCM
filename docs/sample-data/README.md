## 무엇을 보면 되나

**01** — 올리고 적재까지 해보세요. `/admin/data/history` 에 배치가 남고 **되돌리기** 버튼이 생깁니다. 되돌린 뒤 `/admin/forecast-settings` 에서 행 수가 원래대로 돌아오는지 보시면 됩니다.

**02** — 검증 화면에 5가지 오류가 행 번호와 함께 나옵니다.

| 행 | 코드 | 사유 |
|---|---|---|
| 3 | `UNKNOWN_ITEM` | `ITEM999` 가 마스터에 없음 |
| 4 | `INVALID_DATE` | `2026/13/01` — 13월 |
| 5 | `INVALID_DATE` | `2026-02-30` — 없는 날짜 |
| 6 | `REQUIRED` | 수량 누락 |
| 7 | `INVALID_NUMBER` | `62개` — 단위가 붙음 |
| 8 | `DUPLICATE` (경고) | 1행과 키 중복 |

**9행의 `-15`(반품)는 오류가 아닙니다.** 사용 실적의 음수는 정상 데이터이며, 적재는 하되 `core.v_train_demand` 가 학습에서만 뺍니다 (`renew.prd` 12.3).

오류 4건을 적재하지 않고 정상 4건만 넣습니다. **오류 행 CSV 내려받기**를 누르면 원본 컬럼이 그대로 붙어 나오므로, 고쳐서 그대로 다시 올릴 수 있습니다.

**03** — `SKU` · `Transaction Date` · `Quantity` 같은 영문 컬럼이 자동으로 맞춰집니다. 한 번 올리면 매핑 규칙이 `core.column_mapping` 에 저장되어 다음에도 재사용됩니다.

**04** — 데이터 종류를 **확정 수주**로 바꿔서 올리세요. 3행에서 납기일이 수주일보다 빨라 `DATE_ORDER` 로 걸립니다.

## 날짜에 대해

전부 **2026-08-22 이후** 날짜입니다. 현재 DB 의 마지막 실적이 `2026-08-21` 이라 기존 데이터와 겹치지 않습니다.

`replace`(기간 교체) 를 시험하실 때는 **되돌릴 수 없다**는 점을 유의하세요. 지운 원본을 복구할 방법이 없어 되돌리기가 막혀 있습니다.
