# 실데이터 3년치 적재 가이드

간헐수요 품목이 나타나야 STEP 8(Croston 계열)이 값을 합니다. 현재 샘플은 `ADI = 1.00`,
즉 모든 품목이 매달 출고돼서 간헐 품목이 **0개**입니다. 실데이터로 바꾸는 게 목적입니다.

---

## ★ 순서가 중요합니다 — 마스터를 먼저

검증기가 품목코드를 **마스터와 대조**합니다(`renew.prd` 8.3). 마스터에 없는 코드는
`UNKNOWN_ITEM` 오류로 걸립니다.

새 품목코드가 하나라도 있는데 수요부터 올리면 **그 행이 전부 오류가 됩니다.**

```
① 공급처 마스터   →  ② 품목 마스터  →  ③ 수요 실적
```

품목코드가 기존 20개(`ITEM001`~`ITEM020`)와 완전히 같다면 ③만 해도 됩니다.

---

## 준비할 파일

### ① 공급처 마스터 — `SUPPLIER_MASTER`

| 컬럼 | 필수 | 자동 인식되는 이름 |
|---|---|---|
| `supplier_id` | ● | `supplier_id` · `공급처` · `공급업체코드` |
| `supplier_name` | | `supplier_name` · `공급처명` · `법인명` |
| `country` | | `country` · `국가` |
| `standard_lead_time` | | `standard_lead_time` · `lead_time` · `표준리드타임` |

### ② 품목 마스터 — `ITEM_MASTER`

| 컬럼 | 필수 | 자동 인식되는 이름 |
|---|---|---|
| `item_id` | ● | `item_id` · `품번` · `품목코드` · `제품코드` · `자재코드` |
| `item_name` | | `item_name` · `품목명` · `자재명` |
| `supplier_id` | | `supplier_id` · `공급처` |

**MOQ 와 발주단위가 있으면 꼭 넣어주세요.** 지금 `core.item_policy` 가 비어 있어
STEP 10 발주 추천에서 최소 주문 수량을 반영하지 못합니다. 컬럼명은 `moq` · `pack_size`
(또는 `최소발주수량` · `발주단위`)면 자동으로 옮겨집니다.

### ③ 수요 실적 — `DEMAND` ★ 가장 중요

| 컬럼 | 필수 | 자동 인식되는 이름 |
|---|---|---|
| `item_id` | ● | `품목코드` · `SKU` · `품번` |
| `use_date` | ● | `출고일` · `판매일` · `사용일` · `date` |
| `qty` | ● | `출고수량` · `판매량` · `수량` · `quantity` |
| `note` | | `비고` · `메모` |

**형식 규칙**

- 날짜는 `2023-04-15` · `2023/04/15` · `20230415` 만 받습니다. `4/15/23` 은 오류입니다
- 숫자에 단위를 붙이지 마세요. `62개` 는 오류, `62` 는 정상입니다
- 천 단위 쉼표(`1,234`)는 괜찮습니다
- **음수(반품)는 그대로 두세요.** 오류가 아닙니다. 적재는 하되 학습에서만 뺍니다
- CSV 는 UTF-8 · BOM · EUC-KR 을 모두 읽습니다. Excel(.xlsx)·JSON 도 됩니다

**기간** — `renew.prd` 12.1 기준으로 **2023-01 ~ 2025-12** 3년치가 이상적입니다.
최소 24개월은 있어야 계절성을 학습합니다.

## 적재 절차

### 0. 준비 — `sql/14-reload-real-data.sql` 의 1·2부 실행

지금 무엇이 들어 있는지 보고, 미완료 배치를 정리합니다.

### 1. ⚠ 샘플 데이터 삭제 — 같은 파일 3부

**실데이터와 샘플이 섞이면 예측과 백테스트가 전부 오염됩니다.**
1부 결과를 확인한 뒤 3부의 주석을 풀어 실행하세요. 되돌릴 수 없습니다.

옛 예측·백테스트 결과도 함께 지웁니다. 사라진 데이터로 만든 숫자이기 때문입니다.

### 2. 화면에서 올리기 — `/admin/data/upload`

각 파일마다 **데이터 종류**를 맞게 고르고, 적재 방식은 **추가**로 둡니다.
검증 결과를 먼저 보고, 오류가 있으면 **오류 행 CSV** 를 내려받아 고쳐서 다시 올립니다.

파일이 크면(수만 행) 연도별로 나눠 올려도 됩니다. `batch_id` 로 각각 되돌릴 수 있습니다.

### 3. 마무리 — `sql/14` 의 4~6부

학습/검증 경계를 새 데이터에 맞게 옮기고, 격리와 수요 패턴을 확인합니다.

### 4. 다시 돌리기

```
/admin/forecast-runs  → 예측 실행
/model-evaluation     → 백테스트 실행
```

## 파일 규모가 크다면

- Server Action 본문 한도는 **25MB** 입니다 (`next.config.ts`)
- 배포 환경(Vercel)은 **4.5MB** 로 더 낮습니다. 로컬 `npm run dev` 에서 올리세요
- 그보다 크면 연도별로 나누거나, `sql/14` 대신 Supabase SQL Editor 의 `COPY` 를 쓰는 방법도 있습니다.
  다만 그러면 **검증을 건너뛰게 되므로** 권하지 않습니다
