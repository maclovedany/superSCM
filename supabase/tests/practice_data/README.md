# 실습용 데이터 표식·제거 검증 (Task 15)

```bash
bash supabase/tests/practice_data/run-all.sh
```

로컬 PostgreSQL 임시 DB(`scm_test_*`)에서만 돕니다. 원격 Supabase를 가리키면 `guard.psql`이
아무것도 실행하지 않고 멈춥니다 — 이 스위트는 **데이터를 지우는 절차**를 검증하므로 다른 어느
스위트보다 이 가드가 중요합니다.

## 무엇을 증명하는가

| # | 시나리오 |
|---|---|
| S1 | 관리자가 아니면 실습 묶음을 열거나 등기하거나 제거할 수 없다(SCM 품목담당자 포함) |
| S2 | `p_confirm` 없이는 제거되지 않고, 거절된 호출은 아무것도 지우지 않는다 |
| S3 | 실습 품목·배치와 실데이터를 구분한다(품목코드 정규화 포함) |
| S4 | `v_practice_data_status`는 항상 1행이고 영향받는 화면을 알려 준다 |
| S5 | 제거가 실행되고 결과(JSON)를 돌려준다 |
| **S6** | **★ 실데이터가 한 줄도 사라지지 않는다** — `raw.dim_item`, `batch_id`가 null인 행, 실데이터 정책·재고·공급처 |
| S7 | 실습 행은 사라진다(사용 이력·품목 마스터·정책·재고·월말 스냅샷·취합 주기·공급처) |
| **S8** | **★ 사람이 업무를 한 품목은 지우지 않고 사유(`ACTED_ON_BY_USER`)와 함께 보고한다** — 그 품목의 마스터·사용 이력·적재 배치까지 함께 남는다 |
| S9 | 남은 실습 객체는 등기가 유지되어 화면에서 계속 실습으로 표시된다 |
| S10 | 법인 출항 준비기간과 실습 전 Forecast 설정이 원래 값으로 복원된다 |
| S11 | 제거된 라벨은 재사용할 수 없고 두 번 제거되지 않는다 |
| S12 | 등기부는 읽기만 열려 있다(일반 사용자의 직접 쓰기 거절) |

## 설계상 이 스위트가 증명하지 못하는 것

- **화면(Next.js)이 배너를 실제로 그리는지** — 그것은 `lib/practice/model.test.ts`의 순수 모델
  테스트(`showsPracticeBanner` 규칙)와 `npm run build`가 담당합니다. 이 스위트는 DB가 화면에
  내려 주는 값이 맞는지까지만 봅니다.
- **`supabase/practice-data/*.sql`(실습 데이터 본체)가 배포 DB에서 원천 게이트를 통과하는지** —
  그 스크립트는 `raw.dim_item`의 실데이터 93,868행과 5회차 더미 사용 이력의 실제 날짜 분포에
  의존합니다. 로컬 임시 DB에는 그 데이터가 없어 재현할 수 없습니다. 컨트롤러가
  `08-verify.sql`의 확인 쿼리로 적용 직후 직접 확인해야 합니다.

## 다른 스위트와 같은 점

`lib.sh` · `guard.psql` · `auth-stub.psql` · `bootstrap.sh`는 `supabase/tests/item_policy` ·
`master_edit`와 같은 구조입니다. `bootstrap.sh`는 `pg_cron` · `pg_net` 확장이 없어 실패하는
마이그레이션만 골라 건너뜁니다(error.md #31) — 다른 이유로 실패하면 즉시 멈춥니다.
